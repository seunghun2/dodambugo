## 1. 오늘 진행한 핵심 작업 및 조치 사항

### 1-1. 하단 탭바 전환 "즉각 전환 (Instant Cut)" 개편
* **AS-IS**: 하단 탭바 메뉴(홈, 부고장, 정산, 설정) 간 이동 시에도 화면 전체가 좌우로 슬라이딩되어 사용자 피로도가 높고 조작감이 어색했습니다.
* **TO-BE**: 메뉴 간 이동 시 모든 슬라이드 모션을 전면 삭제하고, 누르는 즉시 끊김 없이 화면이 바로 렌더링되는 즉시 전환(Instant Cut) 방식으로 개편했습니다.

### 1-2. 무신사 스타일 "실시간 2중 레이어 스와이프" 정밀 복원
* **AS-IS**: 서브 화면에서 쓸어넘겨 뒤로갈 때, 뒷배경의 복제 오버레이 레이어가 검은색(#000) 배경으로 칠해져 있어 제스처 진행 도중 검은색 화면이 삐져나와 깜빡거렸습니다. 또한 이전 화면의 스크롤 위치가 유지되지 않고 맨 위로 튀는 현상(스크롤 덜컥거림)이 있었습니다.
* **TO-BE**:
  - 뒷배경 색상을 본래 페이지 배경색인 연회색(#f8f9fa)으로 정비하여 흑화 깜빡임을 원천 제거했습니다.
  - 쓸어넘기는 순간 이전 페이지의 스크롤 높이(scrollY)를 복제 레이어의 스크롤 탑 위치로 소수점 단위까지 완벽 동기화(Scroll Sync)했습니다.
  - 무신사 앱처럼 현재 페이지만 오른쪽으로 밀려 나가면서 뒤에 가려져 있던 실시간 이전 화면이 자연스럽고 부드럽게 노출되는 명품 제스처 물리 엔진을 완성했습니다.

### 1-3. FCM 기기 토큰 등록/해제 API의 정석 보안 복구 및 쿠키 포백 구축
* **WKWebView 스토리지 유실 현상 극복**:
  - iOS 하이브리드 앱(WKWebView) 환경에서는 웹의 localStorage가 기기 부팅이나 메모리 상황에 따라 수시로 날아가는 OS 결함이 존재합니다. 이로 인해 기존 코드의 localStorage.getItem('b2b_token') 호출이 null을 반환하여 인증 헤더가 유실되었습니다.
  - 이를 해결하기 위해, 로컬스토리지 외에 document.cookie(세션 쿠키)에서 b2b_token 값을 정규식으로 직접 파싱해 포백(Fallback)으로 적용하는 getB2BToken 함수를 클라이언트에 구축했습니다.
* **이중 크로스 검증을 통한 정석 보안 복구**:
  - 기존에 401 Unauthorized 거부 장애를 임시 우회하기 위해 작성했던 partner_id 검증 해제(프리패스 우회) 땜질 코드를 전면 폐기했습니다.
  - 백엔드 API(push-token/route.ts)에서 Authorization 헤더 및 쿠키 스토어 양쪽 모두에서 토큰을 추출하여 JWT를 해독하고, 본인 소유주 여부를 크로스 체크(401/403 검사)하는 최상급 보안 검증 규격을 온전히 복구했습니다.

### 1-4. Vercel 도메인 오설정 교정 및 실서버 배포 완수
* **실서버 주소 교정**:
  - 앱 내 절대경로 주소가 B2B의 실제 프로덕션 서버인 `https://dodam-next.vercel.app` 이 아닌, 엉뚱한 주소(`https://maeumbugo.vercel.app`)를 바라보고 있어 기기 통신 패킷이 모두 차단되고 있었습니다.
  - 클라이언트 앱 내의 모든 푸시 관련 통신 엔드포인트를 `https://dodam-next.vercel.app` 으로 일괄 교정 완료했습니다.
* **임시 디버깅 UI 소거**:
  - 테스트 및 자가진단 과정에서 생성했던 대시보드의 [알림 테스트 발송] 버튼, 설정창의 [현재 접속 환경] 진단 텍스트, [내 기기 푸시 토큰 복사] 버튼을 소스코드 상에서 흔적조차 남지 않게 깨끗하게 원복(Clean-up)하여 프로덕션 배포를 최종 완수했습니다.

## 2. 기술적 문제점 분석 (트러블슈팅 히스토리)

1. **FCM 토큰 미등록 현상**:
   - iOS 실기기 앱의 설정 하단에서 "FCM 토큰이 아직 기기에 발급되지 않았습니다" 얼럿이 발생했습니다.
   - 이는 기기 OS 수준에서 Firebase SDK(FCM)로부터 토큰 발급 자체를 받지 못하고 있는 상태를 의미합니다. 원인은 아래 3장에서 다룰 Xcode 네이티브 설정 미흡 때문입니다.
2. **실서버 API 정상 확인**:
   - 실서버 백엔드 푸시 발송 API(/api/b2b/send-push)를 직접 찔러 테스트해 본 결과, 500에러 없이 무사히 작동하여 B2B 알림 수신함 테이블(b2b_notifications)에 실시간으로 알림 카드가 100% 무결하게 적재되는 상태를 확인 및 입증했습니다.

## 3. 기기 자체의 진동(찡~) 및 잠금화면 배너 푸시 활성화를 위한 정석 Xcode 가이드

현재 백엔드 서버와 수신함 API는 완벽하게 준비되어 있으므로, 향후 사장님의 폰으로 진짜 진동과 상단 배너("찡~")가 오게 하려면 Mac 컴퓨터에서 아래의 Xcode 네이티브 빌드 설정을 반드시 완료하여 폰에 올려야 합니다.

### [1단계] Xcode 프로젝트 열기
* Mac Finder 또는 터미널에서 `/Users/el/Desktop/dodam/jojo/ios/App` 경로에 있는 **`App.xcworkspace`** 파일을 더블 클릭하여 실행합니다.

### [2단계] 푸시 알림 및 백그라운드 기능 (Capability) 활성화
1. Xcode 좌측 최상단 파일 트리에서 파란색 아이콘의 **`App`** 프로젝트 파일 노드를 선택합니다.
2. 우측 화면 상단 탭에서 **`Signing & Capabilities`**를 선택합니다.
3. 탭 좌측 상단에 위치한 **`+ Capability`** 버튼을 클릭합니다.
4. 검색창에 **`Push Notifications`**를 입력하고 더블 클릭하여 추가합니다.
5. 다시 **`+ Capability`** 버튼을 클릭한 뒤 **`Background Modes`**를 검색하여 추가합니다.
6. 추가된 Background Modes 설정 하단의 체크박스 중 **`Remote notifications`** 항목을 체크해 줍니다.

### [3단계] Apple Developer 인증서 서명 및 App ID 대조
* 동일한 `Signing & Capabilities` 화면의 Signing 섹션에서, 사장님의 Apple Developer 팀인 **Team(FTR72WNB4B)**이 올바르게 매핑되어 프로비저닝 프로파일이 에러 없이 정상적으로 빌드 서명되었는지 확인합니다. (Bundle Identifier인 `kr.co.maeumbugo.bugoon` 과 일치 확인 필수)

### [4단계] Firebase 콘솔에 Apple APNs 인증 키 (.p8) 등록
1. Apple Developer Developer Portal 사이트에 로그인하여 발급으신 **APNs 인증 키 파일 (`.p8` 확장자)**을 준비합니다.
2. Firebase 콘솔에 접속하여 **[프로젝트 설정] -> [클라우드 메시징] 탭 -> [iOS 앱 구성]** 항목으로 이동합니다.
3. 해당 영역에 준비된 `.p8` 파일과 Key ID, Team ID를 업로드하여 등록을 마칩니다. (이 처리가 완료되어야 Firebase가 Apple APNs 서버를 통해 폰으로 알림을 보낼 수 있습니다.)

### [5단계] 실물 iPhone 기기로 앱 빌드 및 실행
1. Xcode 상단 빌드 타겟 장비를 시뮬레이터가 아닌 **사장님의 실물 iPhone 기기**로 선택합니다.
2. **`Command + R`** 키를 눌러 폰에 빌드된 최신 버전의 앱을 새로 덮어씁니다.
3. 앱 실행 시 물어보는 알림 권한 팝업에서 **"허용"**을 선택해 줍니다.

# B2B (부고온) vs B2C (마음부고) 결제 및 주문 접두사 완전 분리 보고서

**작성일**: 2026-08-09  
**목적**: 마음부고(B2C) 라이브 서비스에 **100% 영 영향(Zero Impact)**을 보장하면서, PG사(이노페이) 및 내부 시스템에서 부고온(B2B) 결제/주문을 구분하기 위한 접두사 및 DB 분리 적용 기록.

---

## 1. 개요 및 설계 철학

### 1-1. 최우선 원칙
- **마음부고 기존 로직 1줄도 삭제/수정 금지**: 기존 `COND_`, `CONDTX_`, `CO`, `MG` 로직은 100% 보존.
- **가산적(Additive) 조건식만 추가**: 기존 조건 옆에 `||` (OR) 연산자로 B2B 접두사를 추가하여 B2C 동작에 어떠한 사이드 이펙트도 주지 않음.
- **DB 스키마 하향 호환성 유지**: `condolence_orders`와 `flower_orders` 테이블에 `source TEXT DEFAULT 'b2c'` 컬럼만 추가하여 기존 쿼리와 구조 변경 없이 안전 분리.

---

## 2. 접두사 체계 비교표

| 구분 | 마음부고 (B2C) | 부고온 (B2B) | 설명 |
|------|---------------|-------------|------|
| **부의금 카드결제 moid** | `COND_{timestamp}_{random}` | `BCOND_{timestamp}_{random}` | PG 결제 요청 시 고유 주문 식별자 |
| **부의금 가상계좌 moid** | `CONDTX_{timestamp}_{random}` | `BCTX_{timestamp}_{random}` | 가상계좌/송금 통보 식별자 |
| **부의금 DB 주문번호** | `CO000001` (자동생성) | `CO000002` (자동생성) | DB GENERATED 컬럼 (동일 테이블 공유) |
| **화환 주문번호** | `MG{timestamp}` | `BF{timestamp}` | 화환 주문번호 |
| **DB `source` 컬럼** | `'b2c'` (기본값) | `'b2b'` | 어드민 및 정산 통계용 구분 필드 |

## 3. 수정된 파일 및 라인 상세

### 3-1. DB 스키마 (Supabase)
```sql
ALTER TABLE condolence_orders ADD COLUMN IF NOT EXISTS source TEXT DEFAULT 'b2c';
ALTER TABLE flower_orders ADD COLUMN IF NOT EXISTS source TEXT DEFAULT 'b2c';
```

- **위치**: Line 571, 784, 925, 643

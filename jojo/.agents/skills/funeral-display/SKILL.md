# 장례 정보 표시 규칙

## 핵심 원칙

**모든 장례 표시 로직은 `lib/funeral-display.ts`의 함수를 사용한다.**

하드코딩된 문자열 비교(`=== '무빈소장례'` 등)를 직접 쓰지 않고,
공통 유틸리티 함수를 호출한다.

## 장례 타입 값

| 타입 | DB 값 | 비고 |
|------|-------|------|
| 일반 장례 | `'일반 장례'` 또는 `'일반장례'` | B2C/B2B 공백 불일치 있음 — `isNormalFuneral()` 함수가 둘 다 처리 |
| 가족장 | `'가족장'` | B2C만 생성 가능 (B2B 폼에 옵션 없음) |
| 무빈소장례 | `'무빈소장례'` | |

## 표시 규칙 요약

| 항목 | 일반 장례 | 가족장 | 무빈소장례 |
|------|----------|--------|-----------|
| 빈소 박스 (장례식장+호실) | ✅ | ❌ | ❌ |
| 입관 (B2C) | ❌ **절대 안 보임** | ❌ | ❌ |
| 입관 (B2B) | ✅ (값 있을 때) | ✅ (값 있을 때) | ✅ (값 있을 때) |
| 발인 | ✅ | ✅ | ❌ |
| 장지 | ✅ | ✅ | ❌ |
| 빈소 라벨 | — | "가족장" | "무빈소" |
| 지도 (오시는 길) | ✅ | ❌ | ❌ |
| 화환 보내기 | ✅ | ❌ | ❌ |

## 수정 시 체크리스트

1. `lib/funeral-display.ts`의 함수를 수정한다
2. `__tests__/funeral-display.test.ts` 테스트를 실행한다: `npx jest __tests__/funeral-display.test.ts`
3. 로직이 적용되는 파일 3곳을 확인한다:
   - `app/view/[id]/ViewContent.tsx` (B2C)
   - `app/b2b/view/[id]/ViewContent.tsx` (B2B)
   - `js/view-new.js` (레거시 — ES module import 불가, 인라인 로직)
4. `npm run build`로 빌드 확인한다

## 알려진 제약사항

- 레거시 `view-new.js`는 ES module import가 안 되므로 동일 로직을 인라인으로 유지해야 함
- B2B 생성 폼에 '가족장' 옵션이 없음 (Phase 2 예정)
- B2B에서 무빈소→일반 전환 시 `no_wreath` 플래그가 복원 안 됨 (Phase 2 예정)
